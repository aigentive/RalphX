# RalphX.app v0.56.0

RalphX.app 0.56.0 focuses on execution durability, cached validation evidence, and chat transcript stability during live agent runs.

## User-Facing Changes
- **Task validation now has a persisted evidence path:** task agents can run/cache selected validation commands through RalphX, and reviewers can inspect structured validation summaries in task/review UI instead of relying on ad hoc reruns. [8af5a1ee](https://github.com/aigentive/ralphx.app/commit/8af5a1eecc7ad05dc259b3f279a331b6bfba3588)
- **Task execution completion is more durable:** failed-task retry now re-enters `ready`, completion tool errors no longer act like success signals, and merge cleanup refuses invalid or dirty worktrees before removing task state. [02f44f94](https://github.com/aigentive/ralphx.app/commit/02f44f949972d9424dca91d1f10f207f90670183)
- **Codex task transcripts are more complete:** cleanly finished task executions no longer present as failed runs when completion proof exists, and Codex worker commentary/final-answer messages are persisted into the conversation timeline. [359839d1](https://github.com/aigentive/ralphx.app/commit/359839d101170df56cf1e0d5d4555d445147b0cf)
- **Live chat history is more stable across tab switches:** returning to an in-progress conversation now keeps the persisted transcript visible while the live timeline tail catches up, instead of replacing history with an incomplete streaming window. [cb58db3d](https://github.com/aigentive/ralphx.app/commit/cb58db3dbf051ab5ac0ef5ab761c47a6f983fa0c)

## Fixes And Polish
- **Chat autoscroll better preserves true bottom during streaming:** expanding live rows are observed directly, so the view is less likely to drift while messages or streaming footer content grow. [072c4864](https://github.com/aigentive/ralphx.app/commit/072c4864cdce9830adcc1d2cbc4908b9dadcf710)
- **Streaming timeline finalization is cleaner:** stale streaming-only blocks are pruned when messages settle, and terminal stream errors persist a finalized timeline snapshot. [cb58db3d](https://github.com/aigentive/ralphx.app/commit/cb58db3dbf051ab5ac0ef5ab761c47a6f983fa0c)

## Developer And Maintainer Changes
- **Rust build hygiene baseline:** tunes backend build/test configuration, aligns CI/script entry points, adds benchmark support, and keeps build behavior closer to actual repo-root invocation patterns. [f90ad762](https://github.com/aigentive/ralphx.app/commit/f90ad7620c36b210744de1788139bca2301f0f07)
- **Tauri test helpers are feature-gated:** mock/test support now requires an explicit `test-utils` path in tests, CI, coverage, and local scripts instead of being carried by default builds. [d1da1196](https://github.com/aigentive/ralphx.app/commit/d1da1196f7c19bd87a3eb8a92e7534816a78ac29)
- **Rust integration tests were consolidated into suite binaries:** CI, coverage, `nextest`, helper scripts, and docs now target suite-based integration test entry points with guard scripts for module wiring, feature flags, and test-ID conservation. [24c9e1e9](https://github.com/aigentive/ralphx.app/commit/24c9e1e995e82f3fab9d074be0ff21e2751caf4d)
- **Rust CI now uses a build-once shape with additional guardrails:** shared build artifacts feed shard jobs, doctests expand to workspace scope, push-only full integration coverage is added, and a layering baseline ratchet tracks architectural drift. [5dfa7312](https://github.com/aigentive/ralphx.app/commit/5dfa731282e27ed1f084ee7ebcbec4b048ffef51)

## Known Issues
- The PR Rust macOS build check is currently disabled while its workflow definition remains in place for later re-enablement. [24c9e1e9](https://github.com/aigentive/ralphx.app/commit/24c9e1e995e82f3fab9d074be0ff21e2751caf4d)
