# RalphX.app v0.8.3

RalphX.app 0.8.3 fixes Codex CLI compatibility selection and expands release workflow runner options for Depot-backed builds.

## User-Facing Changes
- **Codex-backed agent messages recover from stale CLI shims:** RalphX now selects the first Codex CLI candidate that supports the required `exec --json` runtime surface, so an old NVM `codex` shim ahead of a compatible Homebrew install no longer blocks Codex-backed messages. [e454b334](https://github.com/aigentive/ralphx.app/commit/e454b334f9282a96d4baf2d2aeae17f671a90855)
- **Codex availability errors are clearer:** `codex exec --help` failures are treated as missing capabilities, so systems with only an incompatible Codex CLI report a structured unavailable state instead of surfacing a raw status 2 command failure. [e454b334](https://github.com/aigentive/ralphx.app/commit/e454b334f9282a96d4baf2d2aeae17f671a90855)

## Developer And Maintainer Changes
- **Release workflows can run on Depot while keeping fallbacks:** Daily Release, Release Build, and Release Publish now expose Depot runner choices alongside GitHub-hosted and self-hosted options; scheduled daily releases and auto-triggered publish default to Depot Linux, and Apple Silicon release builds default to Depot macOS. [ae514f17](https://github.com/aigentive/ralphx.app/commit/ae514f172a8d367c59c8ae3e4cb42057a644942c)
- **Release runner constraints are explicit:** Linux orchestration can select Depot, GitHub-hosted, or a `self-hosted`/`Linux`/`X64`/`ralphx-release` runner; the Intel macOS artifact remains on GitHub-hosted Intel macOS because Depot macOS runners are Apple Silicon. [ae514f17](https://github.com/aigentive/ralphx.app/commit/ae514f172a8d367c59c8ae3e4cb42057a644942c)
