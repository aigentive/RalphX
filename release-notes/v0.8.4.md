# RalphX.app v0.8.4

RalphX.app 0.8.4 improves large-conversation performance, installed-app runtime configuration, and provider-aligned utility workflows.

## User-Facing Changes
- **Large Agents conversations load less work up front:** heavy tool results now render as previews in persisted history and live streams, with full payloads fetched only when an expanded tool call needs them; loaded history is also capped by default to avoid unbounded in-memory transcripts. [868fb28c](https://github.com/aigentive/ralphx.app/commit/868fb28c243deaec0d706e7561cf883dd18c16d6)
- **Installed production builds load packaged runtime configuration more reliably:** bundled `config/` resources and `external-mcp.yaml` are now discovered from the app bundle, with embedded defaults as fallback, reducing missing-tool behavior and unexpected permission prompts in production agents. [47289a0a](https://github.com/aigentive/ralphx.app/commit/47289a0a77a18392a34f4713beae47de4c40e0e5)
- **Codex-owned workflows stay on the Codex runtime for utility helpers:** PR description drafting and session title generation now follow the owning conversation or project ideation harness instead of silently falling back to the default Claude helper path. [6fcac94b](https://github.com/aigentive/ralphx.app/commit/6fcac94bf28ffa7df3b3d4a223eda066cfafc512), [23e9fb52](https://github.com/aigentive/ralphx.app/commit/23e9fb5230bcf13409bd9133f8d0a45b4225301a)
- **Agent workspace publishing recovers from stale repair locks:** workspaces stuck in `needs_agent` after a failed or exited repair agent can now be recovered during startup or workspace hydration, re-enabling publish/update actions while active repairs remain protected. [418394bd](https://github.com/aigentive/ralphx.app/commit/418394bd523200bda1b3dd5bbe3eb7080c929d6f)

## Fixes And Polish
- **Chat composer responsiveness is improved in production WebView:** high-contrast chat input styling no longer relies on expensive `:has()` selector matching that could make large inspected conversations sluggish or unresponsive to clicks. [e8d03a3a](https://github.com/aigentive/ralphx.app/commit/e8d03a3af01508a01070e8dbbc19b29bff18334e)
- **Installed builds reduce canonical-agent config warning loops:** runtime agent config resolution now falls back through packaged runtime/plugin resources when the configured catalog path is unavailable. [e8d03a3a](https://github.com/aigentive/ralphx.app/commit/e8d03a3af01508a01070e8dbbc19b29bff18334e)
- **PR description output is cleaner:** utility prompt updates remove reviewer-hostile caveats about bounded helper context while keeping git data collection scoped to the agent workspace. [23e9fb52](https://github.com/aigentive/ralphx.app/commit/23e9fb5230bcf13409bd9133f8d0a45b4225301a)

## Developer And Maintainer Changes
- **Release CI can use Blacksmith runners:** Daily Release, Release Build, and Release Publish now expose Blacksmith runner options, default scheduled release jobs to Blacksmith, and let ARM and Intel macOS artifacts choose runner providers independently. [2134ce8b](https://github.com/aigentive/ralphx.app/commit/2134ce8bc183c1b1815df8940c20806c155ca50e)
- **macOS release builds install Rust targets explicitly:** the release matrix now runs `rustup target add` and prints installed targets before Tauri builds, preventing the missing `x86_64-apple-darwin` target failure seen on the Blacksmith Intel path. [a8b60763](https://github.com/aigentive/ralphx.app/commit/a8b60763cd084540d0f2383ab2f788cc81f24009)
- **Runtime/config regressions have focused coverage:** this release adds targeted tests around tool-result previews, bundled runtime config, external MCP fallback, agent config root resolution, utility helper harness selection, and stale workspace repair recovery.
