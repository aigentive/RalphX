## False-success review

- `Completed(scheduled:true)` authority: host action returned `scheduled == true` after its own
  run/judge CAS; exactly-once and re-entry absence are covered.
- `Completed(RUN_IN_FLIGHT)` authority: host action observed a blocking run status or judge CAS loss;
  no new run is created and the outcome is explicitly benign.
- `Completed(ALREADY_SETTLED)` authority: claim-time latest-run read proves the judge is no longer
  `Failed`; the request-time twin rejects the same state before persistence.
- `Failed(RUN_CHANGED)` authority: claim-time latest run id differs from persisted `expectedRunId`;
  the Cancelled-latest test proves the create-successor path remains absent.
- `Failed(AUTHORITY_CHANGED|PLAN_GATE_PAUSED|NOT_FOUND)` authority: claim-time automation read and
  status/plan-gate classification; host action is not entered.
- `Failed(HOST_FAILED)` authority: a non-benign host outcome/error after successful claim-time
  revalidation; repository/infrastructure errors are excluded and propagate.
- `FailedStale` authority: `Starting.claimed_at < startup cutoff`; stale rows are terminal and never
  claimable/dispatchable again.
- Every lookup and terminal repository write uses `?`/explicit error mapping. A post-claim latest-run
  repository error propagates and leaves the row `Starting`, with no forged terminal result.
