# Wave B3b tracker

## Scope

- Durable queued-message SEND-NOW intent twin: entity, repositories, migration, AppState wiring, application intent, remote commands, host dispatcher, authority/capability registration, generated transport outputs, and focused tests.
- No frontend, commit, push, install, broad formatting, or cleanup.

## Invariants

- Request validation is fail-closed and persistence is the final request-side effect.
- Deduplication is only for the same unsettled `(conversation_id, queued_message_id)`; distinct queued entries remain independent.
- Dispatcher claims once, revalidates live Project + queue entry + expected active run + harness availability, then invokes the existing `ChatService::send_queued_message_now` seam.
- Infrastructure errors propagate with the claim left `Starting`; stale claims become `FailedStale` and are never replayed.
- A lost queue take is benign `REMOTE_QUEUE_SEND_ALREADY_SENT`; other host failures record that the seam restored the entry to the queue front.
- Wire input carries IDs only; no message content, role, or context type.

## Decisions / findings

- Existing message dispatcher is the runtime-handle precedent; B2c owns the current application-intent error-code and expected-token guard shape.
- User explicitly requires no `cargo clean`; this overrides the repository's normal post-Rust-test cleanup rule for this task.
- The real execute half remains the existing `ChatService::send_queued_message_now` production seam, already covered by its queue/runtime-handoff tests; B3b focused dispatcher tests drive claim/revalidation and assert absence for run-changed, provider-disabled, entry-gone, stale, and re-entry paths. A real successful provider spawn is intentionally not attempted by the startup unit suite.
- False-success review: repo errors propagate after claim, terminal writes are CAS-limited to `Starting`, expected-run mismatch precedes queue take/stop, provider refusal precedes queue take/stop, stale claims are never replayed, and host failure reports front restoration + rehydration.
