# Wave B4c Tracker

## Scope
- Add the remote automation draft intent twin with a pre-allocated `AutomationId` and at-most-once dispatch.
- Re-home the existing `create_automation_draft_for_state` seam into `application/` without changing local-command behavior.
- Extend the B4b remote automation command/repository/dispatcher patterns; no frontend changes.

## Governing invariants
- Persist only after project existence, non-empty name, and all enum values validate fail-closed.
- The persisted `automation_id` is minted once at request time and is the at-most-once authority.
- A claimed request whose automation already exists settles Completed without invoking either conversation factory.
- Stale Creating leases become FailedStale and are never retried: re-drive could create a second automation, setup conversation, and worktree branch.
- Repository/infrastructure errors propagate and leave the claimed row Starting; host/seam failures settle HOST_FAILED after seam compensation.

## Findings / decisions
- Required tracker was absent at turn start; created here before implementation.
- Extended B4b's `remote_automation_commands.rs`, repository status/CAS shape, shared startup dispatcher, migration ordering, registry, ledger, and manifest generation paths.
- Re-homed the local draft-creation seam to `application/automation_draft_creation.rs`; the command module re-exports the original two-argument helper so existing automation tests remain unchanged. The dispatcher uses the separate explicit-ID entry.
- The remote request surface persists the exact remote command fields (`projectId`, required `name`/three enum strings, optional `baseBranch`) after canonical enum parsing; no invalid enum can reach dispatch.
- Dispatcher execution maps `baseBranch` to the local seam's `base_ref`; fields unavailable on the reviewed remote surface (`base_display_name`, pull-request source) remain absent rather than caller-invented.
- Real seam coverage remains in the unmodified automation command tests (selected branch/default/linked/PR/failure compensation). B4c focused tests prove the intent half and the at-most-once pre-existing-ID/stale halves; a real remote success seam would require a git-capable fixture and was not duplicated.
- Loop fingerprint probe produced `spawn_remote_resume_dispatchers@45b243a3c702d4bf`; all seven authority-surface rows were refreshed and the probe was removed.

## False-success review
- Completion authority is exact-ID existence or successful explicit-ID seam execution; same-name dedupe returns the original pre-allocated ID.
- Project and automation repository failures propagate after claim, preserving `Starting`; they never collapse into absence and proceed.
- Completion/failure settlement is CAS-scoped to `Starting`; re-entry cannot execute a settled row.
- Startup stale sweep terminalizes old `Starting` rows to `FailedStale`; it never requeues them, avoiding the double-conversation/worktree factory.
- Existing-ID completion occurs before conversation/workspace creation and has an explicit conversation-absence assertion.
