# Wave B2d tracker

## Scope
- Repoint plan/finalize affordance gates to registered remote twins.
- Add additive remote submit/poll/settle API branches for approval, finalize, and edit.
- Disable remote finalize auto-accept and gate host-only post-approval continuations.
- Add focused tests; do not run Vitest/Playwright.

## Constraints
- Touch only `frontend/src/**` and this tracker; do not edit generated capabilities.
- Preserve local API branches byte-for-byte.
- Use literal twin command names and exact Rust/Tauri input casing.
- Validate with Bun typecheck and the two remote drift/census scripts.

## Findings / decisions
- B1 precedent uses literal submit/poll commands, an `input` wrapper for the submit struct, flat `{ requestId }` polls, Zod validation, fixed-delay bounded settlement, and typed terminal errors.
- Approval/edit terminal results serialize the existing artifact response; finalize accept serializes created task ids while reject returns `{status, sessionId}`, so the client projects accept back to the existing `{status, sessionId}` API contract.
- Plan edit is now owned by `artifactApi.updatePlanArtifact`; `PlanEditor` supplies its displayed `plan.metadata.version` and retains the existing frozen toast.
- Post-approval process continuations remain absent from the manifest and therefore derive `unavailable` through the normal affordance gate.
