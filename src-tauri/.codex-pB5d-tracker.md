## False-success review
- Request authority: task read must exist, status must be in the handler's exact set, and the shared prompt marker must exist before persistence.
- Claim authority: task/status/action payload/marker are re-read fail-closed; mismatch settles `REMOTE_RESUME_AUTHORITY_CHANGED` without handler entry.
- Post-claim race: marker is checked again immediately before recovery; a local answer settles benign `applied:false` without replaying Restart.
- Repository failures before settlement propagate; claimed rows remain `Starting` for the stale sweep rather than reporting success.
- Effects precede `Completed`, and completion write failures propagate rather than fabricating a terminal row.
- Stale task-action claims are `FailedStale` and never replayed; comment records destructive Restart rationale.
